# Orthanc Analytics website

The website of Orthanc Analytics, a project by Leonardo Cristofani and Giulio Presaghi (company in formation), and of its software: Orthanc Polis, Orthanc Solo and Orthanc Logos. It is a single page, static, bilingual (English at the site root, Italian under `/it/`), has no cookies or trackers, and is deployed to GitHub Pages.

- **Pages:** one home page (what Orthanc does, who it is built for, the three products and their features, contact) · Privacy · Cookies · Terms · Accessibility · 404, plus an unpublished draft of the innovative-startup page (see [Legal stages](#legal-stages)). The addresses of the earlier pages (`polis.html`, `investors.html`, `company.html`, `contact.html` and their Italian versions) redirect to the matching section of the home page.
- **Stack:** plain HTML/CSS/JS generated by a zero-dependency Node script (`build.mjs`). No framework, nothing to install for a normal build.
- **Design rules:** [`docs/brand-kit.md`](docs/brand-kit.md). Positioning research: [`docs/competitor-scan.md`](docs/competitor-scan.md). Copy interviews: [`docs/stakeholder-questions.md`](docs/stakeholder-questions.md).

## Build and preview

Requires Node 18 or later.

```bash
npm run build      # writes dist/ and lists any detail still shown as a placeholder
npm run preview    # build, then serve dist/ on http://localhost:8080/
```

`npm run build:strict` fails while the contact address or the email provider is still a placeholder. Use it as the last check before launch.

## Where to change things

| To change | Edit |
|---|---|
| Any text, in either language | `src/i18n/en.json` and `src/i18n/it.json` (same keys in both; the build fails if one is missing) |
| Product features (Polis, Solo, Logos) | `home.polis.features`, `home.solo.features`, `home.logos.features` in both language files |
| Who runs the site: founders, contact address, email | `src/config/site.json` → `company` |
| Email provider named in the privacy policy | `src/config/site.json` → `privacy.emailProvider` |
| Social links (shown in the footer when set) | `src/config/site.json` → `social` |
| Site address (for canonical links, sitemap, social cards) | `src/config/site.json` → `siteUrl` |
| Legal texts | `src/legal/<page>.<lang>.html` (tokens like `{{founders}}` and `{{address}}` are filled from `site.json`; the list is in `src/pages/legal.mjs`) |
| Page structure | `src/pages/home.mjs` (the one page) and `src/pages/legal.mjs`; shared parts in `src/layout.mjs` and `src/components.mjs` |
| Styles / behaviour | `src/assets/css/styles.css`, `src/assets/js/main.js` |

A missing detail is shown on the site as a bracketed placeholder, such as **[ADDRESS] / [INDIRIZZO]** or **[EMAIL PROVIDER] / [FORNITORE EMAIL]**, so nothing is ever invented. Set `company.address` to the street address only (for example `Via Esempio 1`): the site adds “Rome, Italy” / “Roma”. A business address, such as a coworking space or a domiciliation service, avoids publishing a home address.

## Keeping the site current

- **Features.** Every Orthanc Polis feature on the page is backed by the Polis code (Dashboard, Storico elettorale, Punteggi territoriali, Media Monitoring, Clima e Tendenze, Scenari, Calendario, Audit & Qualità AI). Add a feature only once it is live, and keep anything still in preview labelled as such.
- **Figures.** The numbers (7,906 municipalities since 1946, 147 constituencies) come from the Orthanc Polis repository (Electio ingest report, `collegi-full-2022.json`). Update them when the product data changes.
- **Legal.** If you change how the site works (forms, analytics, embeds, a new host), update the privacy and cookie policies and `dates.legalUpdated` first.

## Legal stages

The legal information on the site follows the *Orthanc Analytics website legal information guide* (October 2026). Have a commercialista or lawyer confirm it before relying on it.

**Stage 1: now, before incorporation (current).** The founders run the site and are joint data controllers: the footer, the privacy policy and the terms say so, and describe the company as “in formation” / “in costituzione”. Until the company exists, the site must not show “S.r.l.” (except in the privacy-policy sentence about incorporation), a VAT number, a registered office, “startup innovativa” or the ® symbol.

**Stage 2: after incorporation.**
- Footer: replace the founders block with the company details. The template is kept as an HTML comment in every footer (`POST_INCORPORATION_FOOTER` in `src/layout.mjs`). The VAT number must appear on the home page. Write “i.v.” only if the share capital is fully paid.
- Copyright: `© <year> Orthanc Analytics S.r.l.` (`src/layout.mjs`). Remove “company in formation” / “società in costituzione” (`common.operator` in `src/i18n/*.json`).
- Privacy policy and terms: the company becomes the controller and the operator (`src/legal/privacy.*`, `src/legal/terms.*`). Tell the people who have already written to you.
- Hosting: GitHub Pages’ terms exclude sites used to run a commercial software-as-a-service business. Move to your own domain and hosting, then update the privacy and cookie policies.

**Stage 3: after registration as an innovative startup.**
- Fill the table in `src/legal/startup.it.html` and `src/legal/startup.en.html` and remove the draft notice. First confirm the current wording of art. 25 D.L. 179/2012 with the Chamber of Commerce of Rome.
- Remove `unlisted: true` from the `startup` entry in `build.mjs`: the pages then go into the sitemap and can be indexed. Link them from the home page (“Startup innovativa · informazioni ai sensi dell’art. 25 D.L. 179/2012” / “Innovative startup · information under art. 25 D.L. 179/2012”).
- Update or confirm the information at least once a year.

**Always.**
- Never name a client party or its staff without written consent.
- Don’t offer company shares to the public or publish investment terms; keep the data room behind a request.
- Every email link carries the short privacy note (`privacyNote()` in `src/components.mjs`, `{{mailNote}}` in the legal texts; not needed in the privacy policy itself).
- Don’t add third-party scripts, fonts, embeds, analytics, booking widgets or forms: any of them would need a cookie banner and policy updates.
- If you add a chatbot, it must tell visitors that they are interacting with an AI system (AI Act, art. 50).

## Images and maps (optional tools)

These generate committed files, so the regular build never needs them.

```bash
npm install                                   # dev tools only
npm run map                                   # Europe/Italy dot maps → src/assets/img/*.svg, src/content/maps.json
CHROMIUM_PATH=/path/to/chrome npm run images  # favicon PNGs, logo PNG, social cards (og-en/og-it)
```

The product images (`solo-wards-656.webp`, `logos-teaser-*.webp`, `texture-network-1024.webp`) are monochrome WebP versions of the original artwork. The Solo image is cropped to the ward map and vote totals and is captioned on the site as a concept screen with invented data.

## Deployment

`.github/workflows/deploy.yml` runs `node build.mjs` and publishes `dist/` to GitHub Pages on every push to `main`. Only `dist/` is published: source files, docs, `.idea/` and `main.py` are not.

**Pages source must stay on "GitHub Actions"** (*Settings → Pages → Build and deployment → Source*). If it is switched to *Deploy from a branch*, GitHub also runs its own branch build on every push; that build has no `index.html` to publish, so it replaces the website with this README.

**Custom domain:** configure it in the repository's *Settings → Pages* (with Actions-based deployment no `CNAME` file is needed) and set `siteUrl` in `src/config/site.json` to the new address. With a custom domain, `robots.txt` and `sitemap.xml` sit at the domain root, where search engines look for them.

## Pre-launch checklist

- [ ] Set the contact address (`company.address`) and the email provider (`privacy.emailProvider`) in `src/config/site.json` (`npm run build:strict` passes)
- [ ] Have a lawyer or commercialista review the privacy policy, cookie policy, terms of use and accessibility statement (written for the founders as joint controllers, before incorporation)
- [ ] Confirm the 24-month retention period for emails and the 30-day accessibility reply target
- [ ] Confirm the Orthanc Solo and Orthanc Logos feature lists (`home.solo.features`, `home.logos.features`)
- [ ] Replace the redrawn logo with the original vector if available (`src/assets/brand/orthanc-mark.svg`, then `npm run images`)
- [ ] Decide on a custom domain and update `siteUrl`
- [ ] Interview the team with `docs/stakeholder-questions.md` and refresh the copy

## Accessibility and privacy by design

- No cookies, no local storage, no analytics, no third-party requests (fonts are self-hosted). That is why there is no cookie banner. Adding analytics or embeds would require a consent banner and policy updates.
- Target WCAG 2.1 AA: skip link, landmarks, visible focus, keyboard-operable menu, alt text, `lang` per page, reduced-motion support, reflow at 320 px.

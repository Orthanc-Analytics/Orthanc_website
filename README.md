# Orthanc Analytics website

The company website for Orthanc Analytics and its electoral-intelligence platform Orthanc Polis. It is static, bilingual (English at the site root, Italian under `/it/`), has no cookies or trackers, and is deployed to GitHub Pages.

- **Pages:** Home · Orthanc Polis · Investors · Company · Contact · Privacy · Cookies · Terms · Accessibility · 404
- **Stack:** plain HTML/CSS/JS generated by a zero-dependency Node script (`build.mjs`). No framework, nothing to install for a normal build.
- **Design rules:** [`docs/brand-kit.md`](docs/brand-kit.md). Positioning research: [`docs/competitor-scan.md`](docs/competitor-scan.md). Copy interviews: [`docs/stakeholder-questions.md`](docs/stakeholder-questions.md).

## Build and preview

Requires Node 18 or later.

```bash
npm run build      # writes dist/ and lists any missing company details
npm run preview    # build, then serve dist/ on http://localhost:8080/
```

`npm run build:strict` fails while any required company detail is still missing. Use it as the last check before launch.

## Where to change things

| To change | Edit |
|---|---|
| Any text, in either language | `src/i18n/en.json` and `src/i18n/it.json` (same keys in both; the build fails if one is missing) |
| Company name, address, VAT number, phone, email, PEC, court | `src/config/site.json` → `company` |
| Email provider named in the privacy policy | `src/config/site.json` → `privacy.emailProvider` |
| Social links (shown in the footer when set) | `src/config/site.json` → `social` |
| Site address (for canonical links, sitemap, social cards) | `src/config/site.json` → `siteUrl` |
| Team (Company and Investors pages) | `src/content/team.json` (hidden while empty; see `_example`) |
| Traction metrics (Investors page) | `src/content/traction.json` (hidden while empty; every item needs context, date and source) |
| Investor deck link, data-room email, business model, round | `src/content/investors.json` (each block hidden while empty) |
| Product milestones (Company and Investors pages) | `src/content/milestones.json` |
| Legal texts | `src/legal/<page>.<lang>.html` (tokens like `{{legalName}}` are filled from `site.json`) |
| Page structure | `src/pages/*.mjs`, shared parts in `src/layout.mjs` and `src/components.mjs` |
| Styles / behaviour | `src/assets/css/styles.css`, `src/assets/js/main.js` |

A `null` company detail is shown on the site as **[TO COMPLETE] / [DA COMPLETARE]**, so nothing is ever invented.

## Keeping the site current

- **Dated facts.** The Investors page ("Why now") and the Polis FAQ describe the electoral-law reform ("Stabilicum") as of **6 October 2026**: passed by the Chamber (July) and the Senate (September), awaiting the final Chamber vote. Update both texts and `dates.factsCheckedOn` in `site.json` when its status changes.
- **Figures.** The numbers (7,906 municipalities, 30 elections, 3.07M rows, 147 constituencies, 4 validation gates, 66 checks) come from the Orthanc Polis repository (Electio manifest and ingest report, `collegi-full-2022.json`, `testStabilicum.ts`). Update them when the product data changes.
- **Milestones.** Add new verified milestones to `src/content/milestones.json`, newest first.
- **Legal.** If you change how the site works (forms, analytics, embeds, a new host), update the privacy and cookie policies and `dates.legalUpdated` first.

## Images and maps (optional tools)

These generate committed files, so the regular build never needs them.

```bash
npm install                                   # dev tools only
npm run map                                   # Europe/Italy dot maps → src/assets/img/*.svg, src/content/maps.json
CHROMIUM_PATH=/path/to/chrome npm run images  # favicon PNGs, logo PNG, social cards (og-en/og-it)
```

The product images (`solo-dashboard-*.webp`, `logos-teaser-*.webp`, `texture-network-1024.webp`) are monochrome WebP versions of the original artwork.

## Deployment

`.github/workflows/deploy.yml` runs `node build.mjs` and publishes `dist/` to GitHub Pages on every push to `main`. Only `dist/` is published: source files, docs, `.idea/` and `main.py` are not.

**Pages source must stay on "GitHub Actions"** (*Settings → Pages → Build and deployment → Source*). If it is switched to *Deploy from a branch*, GitHub also runs its own branch build on every push; that build has no `index.html` to publish, so it replaces the website with this README.

**Custom domain:** configure it in the repository's *Settings → Pages* (with Actions-based deployment no `CNAME` file is needed) and set `siteUrl` in `src/config/site.json` to the new address. With a custom domain, `robots.txt` and `sitemap.xml` sit at the domain root, where search engines look for them.

## Pre-launch checklist

- [ ] Fill every company detail in `src/config/site.json` (`npm run build:strict` passes)
- [ ] Name the email provider in `privacy.emailProvider`
- [ ] Have a lawyer review the privacy policy, cookie policy, terms of use and accessibility statement (they are templates written for an Italian company under the GDPR)
- [ ] Confirm the 24-month retention period for emails and the 30-day accessibility reply target
- [ ] Add the team and any publishable traction (`src/content/`)
- [ ] Replace the redrawn logo with the original vector if available (`src/assets/brand/orthanc-mark.svg`, then `npm run images`)
- [ ] Re-check the dated facts (electoral-law status, election window)
- [ ] Decide on a custom domain and update `siteUrl`
- [ ] Interview the team with `docs/stakeholder-questions.md` and refresh the FAQ

## Accessibility and privacy by design

- No cookies, no local storage, no analytics, no third-party requests (fonts are self-hosted). That is why there is no cookie banner. Adding analytics or embeds would require a consent banner and policy updates.
- Target WCAG 2.1 AA: skip link, landmarks, visible focus, keyboard-operable menu and tabs, alt text, `lang` per page, reduced-motion support, reflow at 320 px.
